## ① 구체성 (20점) — "아이디어가 구체적이고 문제 정의가 명확한가"

### 현재 강점
- **문제 정의 슬라이드**: 물류 현장 경험 기반, "상권 데이터 = 추정 / 입찰공고 = 확정 수요 신호" 대비 명확
- **대상 사용자 3군**: 예비창업자 / B2G 납품업체 / 창업 상담기관 명시
- **시나리오 구체성**: 부산 해운대구 급식·식자재, 62건, 29.7점, 21억원 수치 제시
- **해운대 vs 동래 비교**: 같은 부산이어도 품목 구조가 다름 = 차별화 핵심

### 보강 필요
- [ ] **수치 정합성 정리**: 전체 공고 10만건 vs 지역별 집계 단위 혼재 → 집계 기준 정의 1장 추가
  - 10만건 = 전국 2년치 전 품목
  - 4,745건 → 서울 기준 / 220개 = 시군구 커버리지 / 449건 = 단일 지역 기준
  - 슬라이드에서 쓰는 모든 숫자의 집계 기준을 "주석" 또는 "기준 정의" 박스로 명시

### PPT 매핑
| 슬라이드 | 내용 | 커버 여부 |
|---|---|---|
| 3. 문제 정의 | 물류 현장 경험 + 공고=수요 신호 | ✅ |
| 4. 서비스 대상 | 3개 사용자 군 | ✅ |
| 5. 프로젝트 소개 | 10만건/17/220/5종 숫자 | ✅ (정합성 보강 필요) |

## ② 공공데이터 활용 (20점 + 동점 1순위) — 최고 레버리지

| 입찰공고 | 조달청(필수) | count_score, amount_score, recency_score | ✅ |
| 연령별 인구 | 행안부 | consumer_fit_score (소비층 적합도) | ✅ |
| 상가정보 | 소상공인 | competition_score (경쟁 밀도) | ✅ |
| 신생기업 생존율 | KOSIS | adjusted_score (리스크 보정) | ✅ |
| 학교급식 입찰·낙찰 | aT | demand_confidence_score | ✅ (수집 완료) |

- [ ] **"공고=의사 / 계약=실측" 2단 구조 명시**: 슬라이드에서 현재 텍스트만 있음 → 다이어그램 1컷

## ③ 실현 가능성 (20점) — 현재 가장 강한 축

### 현재 강점
- **라이브 데모 배포**: Streamlit Cloud 운영 중 (QR로 즉시 확인 가능)
- **ML 분류기 98%**: 홀드아웃 테스트셋 14,070건 별도 측정
- **전국 커버리지**: 253/255 시군구 = 99.2%
- **데이터 파이프라인**: 나라장터→수집→전처리→점수산정→AI해석 자동화
- **AI 해석**: Gemini API 연동, 수치 근거 인용형 5종 해석

### 심사 Q&A 대비
- ML 98% 과적합 질문 → 홀드아웃 방식 + 약점(사무용품 Recall 0.57) 선제 인정
- 실시간 아니냐 → 정기 배치 + 자동화 파이프라인 다음 단계 계획 명시

## ④ 독창성 (20점) — "기존 유사 서비스와 차별성"

### 현재 강점
- **경쟁 비교표** (`docs/competitive_comparison.md`): 소상공인365 / 나라장터 통계 / 오픈업·비즈맵 vs 본 서비스
- **핵심 차별점**: "민간 소비 추정 → 공공 발주 실측"
- **물류거점 결합**: 경쟁 서비스에 없는 수요 집중지 + 창고 인프라 결합 뷰
- **공고=의사 / 계약=실측 2단 구조**: 수요 신뢰도 레이어가 유일

### 보강 필요

  2. 지역×품목×물류 인프라 3축 결합
  3. AI 해석 + 과해석 방지 구조

## ⑤ 효과성 (20점) — "사회적 가치·파급 효과"

### 현재 강점
- **한계 슬라이드**: "공공수요 참고지표, 창업 성공 예측 아님" 명시
- **기대효과 슬라이드**: 데이터 기반 사전 검토로 감에 의존 감소

### 보강 필요
- [ ] **사회적 가치 3종 명시**:
  1. B2G 정보 비대칭 해소 (공공조달 데이터 = 예비창업자 접근 불가 → 서비스화)
  2. 중소·소상공인 공공조달 진입장벽 완화

         ↓
[전처리 / ML 분류]
  ML 분류기 (18개 품목군 자동 분류, 정확도 98%)
         ↓
[점수 산정 레이어]

  Gemini API → 수치 근거 인용형 5종 해석 + 과해석 방지
         ↓
